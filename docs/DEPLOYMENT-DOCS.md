# Publishing the documentation

How this repository's documentation reaches a reader outside the repository: the site, the PDF
edition, and the one step that has to be done by hand. This covers the **documentation** only.
If a `docs/DEPLOYMENT.md` exists (stream B, platform), it covers deploying the service, not this.

What is published today depends on what has merged. On the day this file was written
(2026-10-13) `main` has the Pages workflow and neither the site nor the PDF edition; both are
planned slices C5 and C4 in [`plans/stream-c-docs.md`](plans/stream-c-docs.md). The sections
below describe how each will work and say what is not there yet.

## The one manual step

**Settings > Pages > Build and deployment > Source = GitHub Actions.** Do this once, as a
repository administrator. No workflow or API token the repository holds can do it. Until it is
done, [`deploy-pages.yml`](../.github/workflows/deploy-pages.yml) fails: first the `configure-pages`
step of the `build` job ("Get Pages site failed"), and the `deploy` job with a "Pages not enabled"
error. Nothing in the workflow is wrong and nothing in it needs fixing.

After the setting is changed, re-run the failed job or start the workflow from the Actions tab
(`workflow_dispatch`). The published address is shown on the `github-pages` environment and in
the job summary; for this repository it is expected to be
`https://konradcinkusz.github.io/payments-bench/`.

## The site

- **What is served.** The contents of `docs/`, uploaded unchanged as the Pages artifact. The
  entry point is `docs/index.html`, a single generated page that loads no external resource
  (decision: [ADR 0006](adr/0006-the-site-loads-no-external-resource.md)). The Markdown files
  in `docs/` are served too, as raw text; they are meant to be read on GitHub.
- **Where it comes from.** `docs/index.html` is generated by `scripts/site-build.mjs` from
  `docs/site/source.html` and `docs/site/status.json`, and committed
  (decision: [ADR 0005](adr/0005-the-documentation-site-is-generated.md)). It is not edited by
  hand.
- **How it is regenerated.** `npm run site:build` rewrites `docs/index.html`.
  `npm run site:check` rebuilds in memory and fails if the committed file differs; CI runs it in
  the documentation lint job, so a stale page cannot merge.
- **When it is deployed.** On a push to `main` that touches anything under `docs/`, and on
  demand from the Actions tab. Concurrent runs queue rather than cancel each other.
- **Status on `main` today.** The generator and the page are not on `main` yet (slice C5). Until
  they are, a deploy would publish `docs/` without an `index.html`.

## The PDF edition

The PDF is built, never committed
(decision: [ADR 0004](adr/0004-the-overview-pdf-is-built-on-demand.md)). The workflow is
`.github/workflows/build-overview-pdf.yml` (slice C4, not on `main` yet). Once it has merged:

- **Dispatch.** Run *Build Overview PDF* from the Actions tab; the PDF is a workflow artifact.
- **Pull requests.** A pull request that touches `docs/papers/**` or `docs/diagrams/**` builds it
  and attaches the PDF as an artifact, so a broken document is caught on the PR.
- **Tags.** Pushing a `v*` tag builds it and attaches it to the GitHub release as an asset.
  This is the only job that holds `contents: write`.

Source for the PDF is `docs/papers/`, a LaTeX presentation of
[`OVERVIEW.md`](OVERVIEW.md), which stays the source of truth.

## What can go wrong

| Symptom | Cause | Fix |
|---|---|---|
| `build` fails at `configure-pages` with "Get Pages site failed", or `deploy` fails with "Pages not enabled" | The Source setting is not "GitHub Actions" | The manual step above, then re-run |
| Site shows old facts | `docs/index.html` was not regenerated | `npm run site:build`, commit; CI would have caught it |
| `site:check` red on a PR | A fact the page reads changed (register, scenarios, findings) | `npm run site:build`, commit the page |
| Deploy waits | Another deploy holds the `pages` concurrency group | Wait; runs are queued on purpose |
