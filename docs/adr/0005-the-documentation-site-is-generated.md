# ADR 0005: The documentation site is generated, not hand-maintained

**Status:** accepted, 2026-10-13

## Context

The site repeats numbers that live elsewhere: how many register rows are open, how many scenario
files and classes exist, how many findings are recorded. A hand-edited page drifts from those
files the first time one of them changes, and nothing would say so. The repository already treats
a document that is silently wrong as a defect ([`REGISTER.md`](../REGISTER.md) is "never silently
wrong").

## Decision

The site is one page, `docs/index.html`, generated by `scripts/site-build.mjs` (slice C5 in
[`plans/stream-c-docs.md`](../plans/stream-c-docs.md)) from one source,
`docs/site/source.html`, and one facts file, `docs/site/status.json`. The generator uses the Node
standard library only: no dependency to install, pin or audit. The facts it needs are parsed
from `docs/REGISTER.md`, `scenarios/` and `docs/FINDINGS.md` rather than typed, so they cannot
drift. The generated page is committed, because Pages serves `docs/` as it is
([`DEPLOYMENT-DOCS.md`](../DEPLOYMENT-DOCS.md)). `npm run site:check` rebuilds in memory and
fails when the committed file differs; the documentation lint job runs it, so a stale page
cannot merge.

## Consequences

- A change to the register, the scenarios or the findings that alters a figure on the page
  fails CI until `npm run site:build` is run and the page is committed. That is the intended
  friction.
- Generated output is committed in one place only, `docs/index.html`; no other build product is.
- The generator is code in a .NET repository. It is documentation tooling and is not referenced
  by any project.
- Until slice C5 has merged this record describes a decision, not a script on `main`.
